Deployment

Open the AmneziaWG 2.0 or 3.1 deployment dialog. The default chooses an available UDP port, a private IPv4 subnet and its first usable interface address. Leave the subnet blank for automatic selection, or enter a network in CIDR notation and an interface address within it. The supported subnet prefix is /16 through /29. Network and broadcast addresses cannot be used for the interface. An unchanged legacy interface using the network address can be retained when editing.

The preflight checks host IPv4 routes and addresses, Docker networks, other VPN container routes, Docker published UDP ports and host UDP listeners. An unavailable discovery command blocks deployment. These checks describe the local server; they cannot detect an unrelated private network behind a remote client or upstream firewall. Choose a network that also avoids your client LANs.

Expand advanced parameters only when needed. Opening it loads editable defaults for the selected protocol version. Keeping it closed generates defaults during deployment. Redeploying an installed protocol preserves its existing configuration; use its settings dialog to change it.

Supported parameters

VersionParameters
2.0Jc, Jmin, Jmax; S1-S4; H1-H4; I1-I5
3.0, existing installations2.0 parameters plus HeaderProtectionKey, ContentPaddingAddition, RekeyAfterTime, RekeyTimeout, RejectAfterTime, KeepaliveTimeout, MaxHandshakeAttempts
3.13.0 parameters plus RandomTrailers and DisableCookies

Jc is the junk packet count; Jmin/Jmax are packet sizes in bytes. S1-S4 are packet paddings. H1-H4 are inclusive, disjoint uint32 ranges or individual values. I1-I5 are client CPS specifications and remain commented in the server configuration. Empty CPS fields are supported. CPS tags include b, r, rc, rd and t; 3.x also supports d, ds and dz. The panel intentionally bounds packet sizes to 1280 bytes, padding addition to 128 bytes and Jc to 128. With Jc enabled, Jmin must be lower than Jmax. Header protection requires S1-S4 >= 12; with RandomTrailers enabled they must be equal to avoid packet loss. RejectAfterTime must be entirely greater than RekeyAfterTime.

The 3.x timing values are integer ranges in the upstream protocol units, usually seconds; MaxHandshakeAttempts counts attempts. HeaderProtectionKey is a shared secret. Treat settings, profiles and backup files as confidential. No parameters from hypothetical future versions are exposed.

Changing an installed protocol

  1. Open clients for the server and select AmneziaWG settings. Read the actual settings and version.
  2. Choose the new port, subnet, interface address or advanced parameters. Confirm that clients will disconnect and their profiles must be updated.
  3. Apply. The candidate is checked with the installed engine in an isolated container before stopping the working container. Server and peer keys are preserved.
  4. Download each existing saved profile again and distribute it. The profile contains its original client private key, updated address, endpoint port and protocol parameters. Do not use key reissue for this operation. Clients created outside the panel require their original profiles; an absent client private key cannot be reconstructed.

A subnet change retains each client's host offset. It also updates clients on pause. An insufficient subnet, an interface address already used by a client, or nonstandard peer routing blocks the change. Existing names, groups, notes, expiry, private keys, preshared keys and other protocols are preserved. A changed server address, subnet or obfuscation may make old profiles incompatible; successful application does not update client devices remotely.

Editing is limited to standard containers managed by the panel. Servers involved in managed or detected external cascades, custom container networks or mounts, custom runtime options, and unfinished bulk issuance are guarded. Disconnect the cascade through its normal workflow or finish the issuance before editing. The panel never silently rewrites a cascade.

Backup, failure and retry

The original container is stopped and retained until the node and database agree. Root-only configuration and service backups are saved under /opt/acontrol/settings-backups/<transaction>. The transaction script resides under /lib65/scripts/. A 180-second systemd watchdog restores the original container and settings if an interrupted transaction is not finalized. New firewall rules created by a failed transaction are removed; pre-existing rules are preserved.

A database journal reconciles saved profiles and paused client addresses after an interrupted request. Before subsequent AWG operations, the panel either finalizes an already committed change or restores the old database data after node rollback. If SSH or rollback cannot be verified, the response explicitly reports an unknown result and later operations remain guarded until recovery succeeds. Reload settings before retrying; a stale revision is rejected. Retained backup files contain secrets and should be removed only after the operator has verified the desired result and no longer needs recovery.

Enabled torrent blocking is installed before the client interface starts, including rollback. Policy changes and collector updates are serialized with settings edits. Resolve unfinished changes before downgrading the database; the migration refuses to delete an unresolved journal.

Развертывание

В окне установки AmneziaWG 2.0 или 3.1 можно оставить автоматический выбор свободного UDP-порта, частной IPv4-подсети и первого доступного адреса интерфейса. Для ручного выбора укажите подсеть в формате CIDR и адрес внутри нее. Поддерживаются маски /16../29. Адрес сети и широковещательный адрес использовать для интерфейса нельзя. При редактировании можно сохранить неизменный адрес старой установки, даже если он совпадает с адресом сети.

До установки проверяются IPv4-маршруты и адреса сервера, сети Docker, маршруты других VPN-контейнеров, опубликованные UDP-порты и UDP-сервисы хоста. Если проверка недоступна, установка блокируется. Локальная проверка не видит сети за удаленными клиентами и внешние межсетевые экраны: подсеть не должна пересекаться также с локальными сетями клиентов.

Расширенные параметры скрыты. Открытие раздела загружает редактируемые значения для выбранной версии. Если раздел не открывать, рабочие параметры генерируются при установке. Повторная установка сохраняет прежний конфиг: для его изменения используйте настройки протокола.

Параметры и версии

Для 2.0 доступны Jc, Jmin, Jmax, S1-S4, H1-H4, I1-I5. Установленная 3.0 также показывает HeaderProtectionKey, ContentPaddingAddition, RekeyAfterTime, RekeyTimeout, RejectAfterTime, KeepaliveTimeout и MaxHandshakeAttempts. В 3.1 добавляются RandomTrailers и DisableCookies. Параметры будущих версий не предлагаются.

Jc задает число мусорных пакетов, Jmin/Jmax — размер в байтах, S1-S4 — дополнение пакетов, H1-H4 — непересекающиеся диапазоны uint32. I1-I5 содержат CPS-пакеты клиента: на сервере они хранятся закомментированными; пустые поля допустимы. Поддерживаются теги b, r, rc, rd, t, а в 3.x также d, ds, dz. Панель ограничивает размер пакета 1280 байтами, ContentPaddingAddition — 128 байтами, Jc — 128 пакетами. При Jc > 0 требуется Jmin < Jmax.

При защите заголовков S1-S4 должны быть не меньше 12. При RandomTrailers = on они также должны совпадать, чтобы избежать потери пакетов. Диапазон RejectAfterTime должен полностью превышать RekeyAfterTime. Тайминги задаются в единицах протокола, обычно в секундах; MaxHandshakeAttempts — число попыток. HeaderProtectionKey — общий секрет, настройки и резервные копии нельзя публиковать.

Изменение установленного протокола

  1. Откройте клиентов сервера и «Настройки AmneziaWG». Панель прочитает действующие параметры и версию.
  2. Измените нужные значения и подтвердите отключение клиентов и необходимость обновить их профили.
  3. Примените изменения. До остановки рабочего контейнера новый конфиг проверяется установленным движком в изолированном контейнере.
  4. Скачайте существующие сохраненные профили повторно и передайте клиентам. Адрес, порт и обфускация обновляются с прежним приватным ключом клиента. Перевыпуск ключа для этого не нужен. Для внешнего клиента потребуется исходный профиль: отсутствующий приватный ключ восстановить нельзя.

При смене подсети сохраняется смещение адреса каждого клиента относительно адреса сети, включая клиентов на паузе. Слишком маленькая подсеть, занятый адрес интерфейса и нестандартные маршруты пиров блокируют изменение. Ключи, PSK, имена, группы, заметки, сроки и другие протоколы сохраняются. Старые профили после смены подсети или обфускации могут перестать подключаться. Обновление на сервере не меняет конфиги на устройствах клиентов.

Изменения разрешены только для стандартного контейнера панели. Серверы с управляемыми или обнаруженными внешними каскадами, дополнительными сетями, монтированиями или нестандартными параметрами контейнера защищены от изменения. Незавершенная групповая выдача также блокирует сохранение. Сначала штатно отключите каскад или завершите выдачу.

Откат и повторный запрос

Исходный контейнер сохраняется остановленным до согласования сервера и базы. Резервная копия конфигов и службы доступна только root в /opt/acontrol/settings-backups/<transaction>, скрипт операции — в /lib65/scripts/. Если операция не подтверждена за 180 секунд, systemd запускает откат. Правила межсетевого экрана, добавленные неудачной операцией, удаляются; прежние сохраняются.

Журнал базы позволяет согласовать сохраненные профили и адреса клиентов на паузе после обрыва запроса. Перед следующими операциями AmneziaWG панель либо завершает уже сохраненное изменение, либо восстанавливает старые данные после отката сервера. При недоступном SSH или неподтвержденном откате возвращается явное сообщение о неизвестном результате. Последующие операции блокируются до успешного восстановления. Перед повтором перечитайте настройки: устаревшая версия конфигурации не принимается. Резервные копии содержат секреты; удаляйте их только после проверки результата и окончания необходимости в восстановлении.

Включенная блокировка торрентов восстанавливается до запуска клиентского интерфейса, в том числе при откате. Смена политики и обновления коллектора согласованы с изменениями настроек. Перед понижением версии базы завершите восстановление операций: миграция не удаляет незавершенный журнал.
