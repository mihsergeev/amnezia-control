Настройка доступа SSH

В карточке сервера можно выбрать прямое подключение или подключение через одну существующую ноду. Обновление панели сохраняет прямой доступ старых серверов и само не перенастраивает их SSH.

Подключение через ноду

В форме сервера выберите «Через сервер» и промежуточную ноду, доступную панели напрямую. Цепочки из нескольких промежуточных нод и циклы не поддерживаются. Удалить используемую промежуточную ноду нельзя.

Для каждой цели панель создает отдельную пару ключей и отдельного пользователя на промежуточной ноде. Имя зависит от публичного ключа, поэтому одинаковые номера серверов в разных панелях не делят одну учетную запись. Приватные ключи остаются в панели.

Эта учетная запись разрешает только TCP-подключение к SSH-адресу и порту выбранной цели. Shell, PTY, обратные TCP-перенаправления, Unix-сокеты, X11 и передача агента запрещены. Ее ключ принимает соединения только с адреса панели, который промежуточная нода фактически увидела при подготовке. Если исходящий адрес панели изменился, повторите подготовку промежуточной ноды.

Для этой роли используется отдельный пользовательский блок OpenSSH в /etc/ssh/sshd_config.d/. Поддерживается установленный OpenSSH с подключением этого каталога через Include и службой systemd, поддерживающей reload. Панель проверяет синтаксис и действующие ограничения до reload. Общий запрет перенаправлений не ослабляется. При неподдерживаемой конфигурации подготовка завершается ошибкой.

Источники ключа и firewall

НастройкаДействие
IP панелиКлюч управления ограничен IP панели. Для подключения через ноду в список добавляется ее IP как кандидат источника, затем адрес проверяется отдельным SSH-соединением.
Указать IP или CIDRЯвный список источников только для ключа управления этой целью. Полезен при NAT и нестандартной маршрутизации.
Без ограничения источникаЯвно снимает проверку исходного IP у ключа управления. Не открывает firewall и не ослабляет отдельный ключ промежуточного доступа.
Добавить разрешения firewallДобавляет точечные разрешения SSH для выбранных источников. Существующие правила сохраняются, firewall не включается и не сбрасывается.
Не менять firewallПанель обновляет ключ и проверяет соединение, не меняя правила firewall.

Ограничение ключа не закрывает SSH для других пользователей и ключей. Если IP панели не задан, для новой настройки нужно указать источники вручную или явно выбрать доступ без ограничения.

IP промежуточной ноды может отличаться от адреса, видимого целью, например при NAT. Панель не снимает ограничения автоматически: неудачная проверка вызывает откат. Укажите фактический исходящий адрес ноды в расширенных настройках цели.

Новый сервер

Автонастройка один раз подключается по паролю, устанавливает ключ и подтверждает вход по нему отдельным соединением. Успешный текст скрипта сам по себе не считается успешной настройкой.

При ручной настройке выполните скрипт под root на целевом сервере. Для маршрута через ноду затем нажмите «Подготовить промежуточную ноду», после чего проверьте сервер. Скрипт меняет только запись ключа панели в authorized_keys, сохраняя остальные ключи.

Изменение работающего доступа

Сначала сохраните адрес SSH отдельно, если изменились хост, порт или пользователь. Это сохраняет номер сервера и связанные профили, не выполняя команды на старом недоступном адресе. После изменения адреса цели повторите подготовку промежуточной ноды, чтобы ограниченный маршрут использовал новый порт и адрес.

Для изменения источников, режима firewall или промежуточной ноды форма сначала показывает предпросмотр. Применение создает резервную копию ключей, сохраняет прежний доступ на время проверки и открывает отдельное соединение по новому маршруту. Лишь после проверки панель завершает изменение.

При сбое восстанавливается прежняя запись ключа и удаляются только собственные новые разрешения firewall. UFW-правила помечаются уникальным комментарием. Для firewalld удаление требует неизменного снимка правил после добавления; чужие изменения не перезаписываются. Если откат не подтвержден, операция остается незавершенной и доступна команда «Восстановить настройку SSH». Новая настройка и удаление связанных серверов блокируются до восстановления.

Незавершенная операция сохраняется в базе панели. При следующем запуске панель пытается согласовать фактическое состояние с журналом. На ноде отдельный процесс предусматривает откат ключа через 120 секунд и своих разрешений firewall через 180 секунд; завершенные операции останавливают эти процессы.

Хранение и удаление

Публичные ключи и ограничения находятся на нодах. Приватный ключ промежуточного доступа хранится в data/ssh/jump_<server_id>. Host key проверяется отдельно у промежуточной ноды и цели; изменение известного ключа блокирует подключение.

После подтвержденного перехода на прямой маршрут или другую ноду панель пытается отозвать только свой публичный ключ в прежней роли. При удалении цели такой отзыв выполняется до удаления приватного ключа из панели. Если прежняя нода недоступна или ее роль изменена вне панели, новый маршрут и удаление сохраняются, а панель сообщает, что старый промежуточный доступ не отозван. При необходимости этот публичный ключ нужно удалить вручную.

Новый сервер с повторно использованным номером получает новый приватный ключ и другую учетную запись. Системный пользователь и его пользовательский блок OpenSSH автоматически не удаляются: после успешного отзыва в этой роли не остается ключа панели.
