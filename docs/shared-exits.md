# Общий выход каскадов

Несколько разных входов могут использовать один выход. Каждый вход остается участником только одного каскада. Узел выхода нельзя одновременно назначить входом. Проверяются также разные записи сервера, которые указывают на один физический узел.

Поддерживаются AWG 3.1, VLESS REALITY и GRE, включая сочетание разных транспортов на одном выходе. Новые каскады получают отдельные интерфейсы, конфигурации, контейнеры, порты, службы восстановления и правила выпуска трафика. GRE использует отдельный ключ туннеля для каждой пары; этот ключ разделяет туннели и не шифрует трафик.

Порты и внутренние сети резервируются также для незавершенных и неудачных установок. Повторная установка сохраняет параметры пары. Удаление одного каскада освобождает только его ресурсы и не перезапускает соседние каскады на общем выходе. Внешние туннели и конфигурации VPN-клиентов не принимаются под управление автоматически.

Существующие каскады сохраняют прежние имена ресурсов и параметры. Обновление панели не переносит их на новую схему и не пересобирает протоколы клиентов.

## Совместимость при откате

Новая схема ресурсов обозначена `runtime_layout=2` во внутренних параметрах каскада. Старые версии панели ее не поддерживают: они могут обращаться к прежним общим путям при переустановке или удалении. Поэтому возвращать старый код при наличии таких каскадов нельзя, даже если на выход приходится только один вход.

Миграция блокирует понижение схемы при наличии каскадов новой схемы или нескольких входов с общим выходом. Для отката сначала требуется штатно разобрать новые каскады подходящей версией панели и проверить сохранность оставшихся. Если новые каскады уже используются, предпочтительно исправление с обновлением вперед.

Изоляция ресурсов и резервирование относятся к одной базе панели. Попытка другой панели использовать уже занятые имена ресурсов завершается отказом проверки владения, без принятия чужого каскада под управление.
